# OpenCCF - Open Corporate Carbon Footprint

[OpenCCF](https://openccf.org/) is a common, machine-readable structure for exchanging GHG Protocol-aligned carbon footprints between systems: open, CC0, and framework-agnostic.

CarbonSutra provides native OpenCCF outputs, letting you turn estimation data into this sophisticated and globally recognized reporting standards with a single API call. Instead of dealing with custom formatting programs, messy spreadsheets or locked-in datasets across Scope 1, 2, and 3 emissions, the calculations are mapped automatically. This removes manual data entry and lets you easily move your carbon inventory across enterprise tools.

This update makes audits much faster for sustainability managers, accountants, and auditors. CarbonSutra already provides clear, step-by-step explanations for every calculation. Formatting this transparent data into the OpenCCF standard allows you to send verified carbon totals straight into ESG, registries, and compliance reports like CSRD or GHG Protocol without losing context.

For software developers and tech teams, CarbonSutra becomes a simple, plug-and-play carbon engine. You can keep using our zero-storage clustering feature to group transaction batches under custom tags without building extra database structures. Your software can now deliver standard-compliant ESG outputs instantly, saving backend development time and simplifying supply chain tracking.

## Getting output in OpenCCF format

Internally, the API for OpenCCF uses the [clustering](https://carbonsutra.com/special-features/clustering) functionality in which the developer eliminates the need to store emission calculation results by assigning a self-declared tag to it. These tags are called cluster names and they can be added to any calculation within CarbonSutra. The endpoint: /cluster-data accepts this tag and gives the output of all calculations in granular format in JSON. OpenCCF's API invokes the same API internally.

Hence, there are two inputs for OpenCCF:

1. Cluster Name - which is used to group all emission calculations in the report
2. Report Configuration - An optional field of header data in JSON format which will be used in OpenCCF's output.

Both these are passed to /openccf endpoint to get the result in a YAML format, as specified by OpenCCF's data model.

The report configuration has following fields:

- `report_id`: `<Report identifier>`
- `company_name`: `<Legal or trading name of reporting company>`
- `region`: `<Location of the reporting entity, as an ISO 3166-1 country code, like "GB" or "US">`
- `period_start`: `<Reporting period start date in YYYY-MM-DD>`
- `period_end`: `<Reporting period ending date in YYYY-MM-DD>`
- `horizon`: `<Specify methodology used to calculate CO2 equivalencies. Values are GWP20, GWP100 (default) or GWP500>`
- `report_status`: `<Incomplete, Self-completed, Third-party completed or Third-party audited>`

An example of this field in JSON is:

```json
{
  "cluster_name": "KrugerBrent-H1-2026",
  "report_config": {
    "report_id": "KB-Asia26-Part-1",
    "company_name": "Kruger-Brent Manufacturing Asia-Pacific",
    "region": "AU",
    "period_start": "2026-01-01",
    "period_end": "2026-06-30",
    "horizon": "GWP100",
    "report_status": "Self-completed"
  }
}
```

The data in report configuration serves as the information in header fields of OpenCCF. CarbonSutra's internal smart matching algorithm works here too. For example, the report status of 'completed by third party' will result in expected "THIRD-PARTY COMPLETED' and horizon value of ' = 100' will output the correct GWP100.
